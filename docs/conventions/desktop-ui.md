# Desktop UI 开发规范

> 状态：Normative（强制）
>
> 适用范围：`apps/desktop/src/renderer` 及 Desktop renderer 使用的视觉组件
>
> 设计方向：Quiet Workbench / 克制的桌面工作台

本规范用于让 Pragma Desktop 的页面保持同一套视觉语言，并减少常见的 AI 生成界面特征：
无意义的圆角卡片、层层边框、过多分割线、虚高字重、任意字号、悬浮阴影和每块内容都带标题说明。

本规范不要求一次性重做现有页面。新增 UI 必须遵守；修改旧页面时，只收敛本次触及的区域，禁止为了
“统一风格”顺手重写无关交互或信息架构。

## 1. 设计定位

Pragma 是长时间使用的 Agent 工作台，不是营销网站，也不是组件陈列页。界面应当像一件安静、可靠的
生产工具：内容优先、结构清晰、状态可信、装饰克制。

保留现有产品辨识度：

- 灰白画布、浅灰绿导航、石墨色文字和鼠尾草绿强调色。
- 左侧应用导航，以及 Home、Missions、Studio、Evaluations、Usage、Settings 的现有信息架构。
- Home 的单一 Mission composer、目录/详情分栏、Flow canvas 等已经形成产品心智的结构。

所有页面遵循以下视觉优先级：

1. 内容和任务状态。
2. 当前主操作。
3. 页面与区域层级。
4. 导航和辅助操作。
5. 品牌与装饰。

不要通过给每一层内容增加容器来表达层级。表达层级的默认顺序是：

```text
版式位置 → 间距 → 字号/颜色 → 背景色差 → 边框 → 阴影
```

只有前一种方式不足以表达关系时，才使用后一种。

## 2. 当前基线与收敛目标

在分域拆分前，`styles.css` 曾超过 16,000 行，包含约 387 处圆角、1,000 余行边框声明、
200 余处字重声明和 500 余个直接颜色字面量。字号集中在 10–13px，但同时存在大量零散尺寸；字重存在
`520`、`590`、`650`、`680`、`730`、`740` 等过细分值。部分选择器在文件相距数千行的位置重复覆盖，
例如按钮、Settings、Studio、Missions 和 provider/runtime card。

这些实现会产生三个结果：

- 页面由许多“看起来都很重要”的小块组成，主次关系反而变弱。
- 同类组件在不同页面拥有略有差异的圆角、字重、边框和 hover，形成拼接感。
- 后续开发者只能继续追加覆盖规则，难以判断哪个值才是设计意图。

收敛目标不是“全面扁平化”，而是减少没有语义的视觉层。每个可见边界都必须说明它在区分什么。

## 3. 四条强制规则

### 3.1 单边界规则

一个控件或内容区域只能有一层可见边界。以下情况禁止出现：

- 有边框的 section 内再放一组有边框的 card。
- 有边框的组合输入框内，`input`、`textarea` 或 `select` 再显示自己的边框或焦点环。
- 同一行同时使用外框、上下分割线和阴影。

### 3.2 单主操作规则

一个页面或一个对话框的可见区域最多有一个实心主按钮。其余操作使用次按钮、文字按钮或菜单。不要把
“新建”“导入”“运行全部”“保存”等多个操作同时画成主按钮。

### 3.3 默认无卡片规则

`div`、`section` 或设置分组默认是无边框、无阴影、无圆角的普通内容区。只有满足以下至少一项时才使用
独立 surface：

- 对象可以被整体选择、拖拽、展开或打开。
- 对象需要与相邻对象独立比较，例如 provider、runtime 或统计摘要。
- 内容是浮层、弹窗、popover 或全局错误。
- Home composer 这类页面唯一的任务焦点。

“为了好看”“为了把内容包起来”“其他页面也有卡片”不是使用卡片的理由。

### 3.4 默认无阴影规则

普通页面、列表行、设置项和静态卡片不使用阴影。阴影只表达 z 轴关系：dialog、popover、menu、拖拽中
对象，或 Home 唯一主 composer。hover 通过浅背景或文字颜色变化表达，不通过上浮和加深阴影表达。

## 4. Design Tokens

视觉值必须优先使用语义 token。除 provider 品牌色、数据可视化序列和确有语义的特殊状态外，不得在
组件选择器中新增 hex、rgb、任意圆角或任意字重。

### 4.1 颜色

| Token                 | 值                      | 用途                           |
| --------------------- | ----------------------- | ------------------------------ |
| `--ui-canvas`         | `#f8f9fb`               | 应用主画布                     |
| `--ui-rail`           | `#f1f3f2`               | 应用导航和固定侧栏             |
| `--ui-surface`        | `#ffffff`               | 输入区、独立对象、浮层         |
| `--ui-surface-subtle` | `#f5f7f6`               | hover、轻量分区                |
| `--ui-selection`      | `#e9f0ec`               | 选中态，不表示成功             |
| `--ui-text`           | `#1d211f`               | 标题和正文                     |
| `--ui-text-secondary` | `#67706a`               | 描述、元数据                   |
| `--ui-text-disabled`  | `#919994`               | 禁用或非信息性装饰，不用于正文 |
| `--ui-line`           | `#e4e8e5`               | 普通分隔                       |
| `--ui-line-strong`    | `#d8ded9`               | 输入边界、浮层边界             |
| `--ui-accent`         | `#587968`               | 主操作、交互强调               |
| `--ui-accent-strong`  | `#456454`               | hover、文字链接、强调文本      |
| `--ui-danger`         | `#9d3f34`               | 错误和破坏性操作               |
| `--ui-danger-subtle`  | `#fff8f7`               | 错误背景                       |
| `--ui-focus`          | `rgb(88 121 104 / 20%)` | 焦点外环                       |

现有 `--background`、`--sidebar`、`--surface`、`--text`、`--muted`、`--green` 等 token 可以在迁移期
作为别名保留。不要在一个改动中机械替换全文件。

颜色使用规则：

- 强调色只用于操作、选中标记和关键运行状态，不用于大面积装饰背景。
- `--ui-text-secondary` 可以承载正文；`--ui-text-disabled` 只用于 disabled、placeholder 或非关键信息。
- 状态不能只靠颜色表达，必须同时有文字、图标或形状变化。
- 品牌色只出现在品牌 logo/mark 内，不扩散为页面主题色。

### 4.2 字体与字号

默认字体：

```css
font-family:
  Inter,
  "SF Pro Text",
  "SF Pro Display",
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

代码、ID、路径和运行日志使用：

```css
font-family: "SFMono-Regular", "Cascadia Code", Consolas, monospace;
```

| 层级          | 字号 / 行高   | 字重  | 用途                       |
| ------------- | ------------- | ----- | -------------------------- |
| Home display  | `28px / 1.2`  | `600` | 仅 Home 空白态主标题       |
| Page title    | `24px / 1.25` | `600` | 每页唯一 `h1`              |
| Section title | `16px / 1.4`  | `600` | 主要 section 标题          |
| Row title     | `14px / 1.45` | `500` | 列表对象名、设置项名称     |
| Body          | `14px / 1.5`  | `400` | 正文、解释文本             |
| Control       | `13px / 1.4`  | `500` | 按钮、输入、tabs、导航     |
| Metadata      | `12px / 1.45` | `400` | 时间、状态说明、次级信息   |
| Micro label   | `11px / 1.35` | `500` | 表头、短标签；不得承载段落 |
| Code          | `12px / 1.55` | `400` | ID、路径、代码和日志       |

只使用 `400 / 500 / 600` 三档常规字重。品牌字标、关键总数或确需强调的错误标题可以使用 `700`。
禁止新增 `520`、`590`、`650`、`680`、`730` 等任意字重。不要同时用大字号、粗体、深色和卡片边界
重复强调同一内容。

补充规则：

- 一个页面只有一个 `h1`；section 从 `h2` 开始，不跳级。
- 中文不使用全大写语气。英文 eyebrow 可以使用大写，但字号至少 11px、字距不超过 `0.08em`。
- `strong` 表达语义强调，不作为每个列表项标题的默认样式工具。
- placeholder 不是 label；表单始终保留可见 label。

### 4.3 间距

使用 4px 基线：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。不得新增 13px、17px、19px、21px、
27px 等只为“看起来差不多”的间距。

| 场景             | 推荐值                         |
| ---------------- | ------------------------------ |
| 图标与文字       | `8px`                          |
| 同一控件内部     | `8–12px`                       |
| 同组字段或列表行 | `12–16px`                      |
| 标题与正文       | `4–8px`                        |
| section 之间     | `24–32px`                      |
| 页面主区 padding | 水平 `32–64px`，垂直 `40–56px` |
| 紧凑列表行高     | `40–44px`                      |
| 常规列表行高     | `48–56px`                      |

同一页面最多使用两种列表密度。不要通过给每项增加 padding、圆角和外边距来制造“呼吸感”。

页面内容区的底部 padding 默认必须与左右 padding 相同；紧凑断点也遵循同一规则。可滚动列表或看板必须
占满页面骨架分配的剩余高度，并在自己的内容区内滚动。禁止用固定 `vh`、任意 `max-height` 或提前结束的
滚动容器制造大于页面 padding 的底部空白。

### 4.4 圆角

| Token               | 值      | 用途                              |
| ------------------- | ------- | --------------------------------- |
| `--ui-radius-sm`    | `4px`   | 标签、code、紧凑控件              |
| `--ui-radius-md`    | `6px`   | 按钮、输入框、列表选中背景        |
| `--ui-radius-lg`    | `10px`  | 独立 surface、menu、dialog        |
| `--ui-radius-round` | `999px` | 状态点、头像、switch、真正的 pill |

结构区域、页面 section、表格、普通列表和左右分栏使用 `0`。圆角必须与对象尺度匹配，禁止新增
`7px`、`8px`、`9px`、`11px`、`13px`、`14px`、`15px`、`16px` 等中间值。

`999px` 只用于 pill、switch、圆形 avatar 或状态点；普通按钮和搜索框不做胶囊形。

### 4.5 边框与阴影

标准边框只有两种：

```css
border: 1px solid var(--ui-line);
border: 1px solid var(--ui-line-strong);
```

标准焦点和浮层阴影：

```css
box-shadow: 0 0 0 3px var(--ui-focus);
box-shadow: 0 16px 40px rgb(20 31 25 / 12%);
```

- 列表只在相邻行之间放分割线，不同时包外框。
- 页面侧栏与主内容之间最多一条结构分割线。
- 静态 surface 不使用阴影；menu/dialog 的阴影不随 hover 改变。
- 不使用渐变边框、发光、玻璃拟态或多层彩色阴影。

## 5. 页面骨架

### 5.1 应用 Shell

- 主导航默认宽 `240px`，允许在 `200–360px` 内拖动；收起导航固定为 `88px`，收起态不显示拖动柄、
  不响应拖动，重新展开后恢复上次保存的宽度。
- Missions 二级导航默认宽 `300px`，允许在 `240–420px` 内拖动；Studio、Evaluations、Settings 二级导航
  默认宽 `242px`，允许在 `200–420px` 内拖动。各区域独立保存宽度到本地，下次启动继续生效。
- 拖动柄默认不可见，仅在 hover、键盘 focus 或拖动时显示强调色；支持左右方向键微调、Shift + 方向键
  大步调整、Home/End 跳到最小/最大宽度。不要用常驻粗分割线表达可拖动区域。
- 导航选中态只使用一层浅背景和前景色变化；不增加描边、阴影、额外字重或位置标记。
- 除非产品需求明确指定，导航、tab、列表和分段控件的选中态禁止添加左侧竖线、顶部/底部短线、角标或
  其他装饰性位置标记。这类模板化标记不能作为默认设计手法。
- 导航图标统一 Phosphor regular，常规 `20px`，主导航最多 `22px`。
- 导航区和内容区的背景色差已经足够时，不再增加右侧阴影。

### 5.2 Home

- 保持开放画布和一个主 composer；composer 是页面唯一允许同时拥有 surface、边框和轻阴影的对象。
- workspace、executor、model、permission 属于 composer 内部控制，不拆成多个选择卡片。
- 环境图形或 Agent constellation 只能作为低对比背景，不与标题、输入和运行状态争夺注意力。
- 空白区域是结构的一部分，不用推荐卡片、提示卡片或快捷操作卡片填满。

### 5.3 Missions / Studio / Evaluations 目录页

- 使用“目录栏 + 工作区”平面分栏。外层可以有一条边界，但内部列表不再逐项卡片化。
- Missions、Studio、Evaluations、Settings 等固定二级导航统一使用 `--ui-rail`，相邻内容区使用 `--ui-canvas`；
  背景色差已经表达分栏时，不再增加结构分割线或阴影。
- 目录页的二级导航和内容工作区直接落在对应背景层上，不再套白色容器、面板边框或圆角卡片。
- 固定二级导航项从顶部按紧凑行高依次排列，不随侧栏或窗口高度拉伸、平均分布；列表下方空间保持留白。
- 选中行使用 `--ui-selection` 与必要的前景色变化；hover 只用 `--ui-surface-subtle`，默认不添加位置标记。
- 行内只显示决策所需的名称、状态和一组次级信息。更多操作在 hover/focus 后出现或进入菜单。
- 详情页通过标题、section 间距和背景区分结构；仅交互对象使用 surface。
- 进入详情页时默认保留所属模块的二级导航，只替换右侧工作区内容；不得通过页面级条件渲染卸载目录骨架，
  也不得让详情组件覆盖二级导航。返回列表后应保留原有导航宽度、选中项和滚动位置。
- 主导航、二级导航和内容区构成 Desktop 的基础页面骨架。除非产品需求明确说明进入沉浸式全屏工作区，
  页面或详情组件不得自行隐藏、跨越或重建这套骨架。

### 5.4 Settings

- Settings 是偏好列表，不是卡片画廊。普通设置使用无外框的 label/value 行或 section。
- 常规设置项通过稳定行高和垂直留白分组，项与项之间不使用分割线。
- Provider、Runtime 等可独立启停、展开、进入详情的对象可以使用一个独立 surface；对象内部字段不再
  继续套 card。
- Runtime 目录项的模型摘要使用紧凑的次级底栏，并以 `--ui-surface-subtle` 和身份区形成背景色差；不为
  简短的模型数量预留大块空白。
- 高级设置默认折叠或分组，不使用醒目的装饰性标题条。

### 5.5 Usage

- 总量可以作为一个主摘要；趋势和明细优先共用同一数据工作区，而不是每个指标一个卡片。
- 桌面宽度下数据工作区默认使用可用内容宽度，不用过窄的居中 `max-width` 制造无意义的左右留白。
- 摘要指标通过栅格、对齐和留白建立层级，不使用整块白底或上下边框伪装成卡片。
- 图表网格、坐标轴和列表分隔使用低对比线；颜色只编码数据或状态。
- 趋势图必须显示可读的横纵坐标刻度；数据节点在 hover 和键盘 focus 时显示准确日期与完整数值，不能只
  依靠折线位置让用户估算。
- 折线、面积和端点必须保留在 SVG 绘图区内；不要依赖 `overflow: visible` 绕过裁切。
- Usage 排行不展示已删除的 Mission、Expert、ExpertTeam 或 Flow；总览仍保留真实历史消耗。列表顶部用
  统一的低对比提示说明统计包含关系和删除过滤规则。
- 数字可以使用 `600/700`，单位、时间范围和说明保持 `12–14px / 400`。

### 5.6 Dialog / Menu / Drawer

- Dialog 和 menu 是浮层，可以使用 `--ui-radius-lg`、strong border 和浮层阴影。
- Dialog header、body、footer 不需要各自完整边框；只在滚动内容与固定 footer 之间使用一条分隔线。
- 危险确认要说明对象、影响和可恢复性，不依靠红色大卡片制造严重感。
- 导出、删除或批量操作等会作用于具体资源的弹窗，不默认选择第一个资源；必须由用户明确选择后才能执行。

## 6. 组件规范

### 6.1 Button

- 常规高度 `36px`，紧凑工具按钮 `32px`；纯图标按钮的可点击区域不得小于 `32 × 32px`。
- 主按钮：实心 accent、白字、`6px` 圆角。每个可见任务区最多一个。
- 次按钮：默认透明或 subtle 背景；只有需要明确边界时使用 strong border。
- 文字按钮：用于返回、取消、编辑、查看详情等低优先级动作。
- 破坏性按钮：默认克制，仅在最终确认步骤使用 danger 色。
- 禁止 gradient、pill、hover 上浮、按钮内全大写和无语义 sparkle 图标。

### 6.2 Input / Select / Textarea

- 常规高度 `36–40px`，圆角 `6px`，背景为 surface，边框为 strong line。
- focus 只显示一层 3px 外环；组件内部原生控件必须清除自己的 border、outline 和 shadow。
- label 使用 `12–13px / 500`；帮助文本和错误文本使用 `12px / 400`。
- 同一行不要同时出现永久 label、全大写 eyebrow、placeholder 和帮助文本来描述同一件事。
- 空白新建表单初次展示时不显示校验错误，也不预先标记 `aria-invalid`；字段失焦或用户首次提交后再显示
  对应错误，修正后即时清除。无效提交必须聚焦第一个错误字段，不能只在表单底部显示通用错误。
- Enter 触发提交或发送的输入框必须忽略输入法组合期间的按键，包括 `isComposing` 和 Chromium
  `keyCode === 229` 的兼容情况。中文、日文、韩文输入法第一次 Enter 只确认候选文字，组合结束后的下一次
  Enter 才能提交。
- 资源名称、描述、标签、指令和提示词的长度不得在页面内写数字常量。统一使用
  `@pragma/shared` 的 `PRAGMA_TEXT_LIMITS`、Unicode 计数和截断函数；Desktop 合约、Interpreter Schema、
  编译器迁移和 DSL 创作说明必须引用同一来源。长度按 trim 后的 Unicode code point 计算，不能用
  JavaScript `string.length` 直接计数，也不能静默截断已持久化的旧数据。
- 有字符上限的可编辑 input、textarea 和富文本输入区，必须在控件下方靠右显示 `当前字数/上限`，例如
  `0/50`。单独的计数值统一使用 `CharacterCount`；组件同时承载错误或帮助文本时，可以复用其右侧计数
  槽。帮助文本居左、计数居右，不能等到超限后才显示上限。

### 6.3 统一交互组件

- 业务页面不得直接展示由浏览器或操作系统绘制的原生 UI。`select`、原生 `<dialog>`、
  `window.alert()`、`window.confirm()`、`window.prompt()` 和带平台默认外观的文件选择入口，必须由 Desktop
  统一交互组件替代。
- 单选下拉统一使用共享 Select/Menu 组件；触发器、菜单、选中态、disabled、loading、键盘导航和焦点恢复
  不得由页面各自实现。组件内部可以使用语义化原生元素，但不能暴露平台默认外观。
- 通过 Portal 渲染的 Select/Menu 必须声明所属 Overlay。父级浮层的 outside-dismiss 必须把所属子菜单视为
  内部交互；选择筛选值不能意外关闭父级弹窗，只有明确选择最终对象、Escape 或真正的外部点击才能关闭。
- 弹窗、确认框和 drawer 统一使用共享 Dialog/Overlay 组件；必须处理焦点圈定、Escape、返回焦点、遮罩、
  标题关联和危险操作语义。禁止用系统弹窗绕过产品视觉与可访问性规范。
- 新建、导出、绑定或批量操作中的资源选择器不得默认选择列表第一项；只有编辑已有对象或产品需求明确
  提供持久默认值时才能预选。用户筛选列表不会被视为最终选择，也不能因此关闭选择弹窗。
- 新功能立即遵守；修改仍使用上述原生 UI 的旧页面时，必须在本次触及范围内完成迁移，不得新增例外。

### 6.4 List / Table

- 同类数据默认使用行，不使用 card grid。
- 表头 `11–12px / 500`，正文 `13–14px / 400`，对象名最多 `500`。
- 行之间可用一条 `--ui-line`；表格外框、行外框和 cell 外框不能同时存在。
- hover/focus 不改变布局、行高或字重，避免文字抖动。

### 6.5 Badge / Status

- Badge 只表示短状态、类型或不可编辑的属性，不用于普通分类标题。
- 状态文案使用事实：`运行中`、`需要配置`、`失败`；避免 `SMART`、`AI POWERED` 等营销词。
- 同一状态只使用一个 badge，不再同时配彩色 card、彩色 icon background 和粗体标题。

### 6.6 Icon

- 使用现有 `@phosphor-icons/react` 或已有品牌资产，不手写 SVG、emoji 或 CSS 图标。
- 常规 icon 为 `16 / 18 / 20px`，主导航最多 `22px`。同一工具栏只用一个尺寸。
- icon 默认继承文字颜色。只有状态或品牌 logo 使用独立颜色底。
- 有文字的按钮不需要为每个动作都配 icon；icon 不能替代不明确的 label。

### 6.7 Empty / Loading / Error

- 空态由一个短标题、一句解释和至多一个操作组成，默认不放入大圆角虚线卡片。
- loading 保留当前布局，优先使用行内状态或 skeleton，避免整个页面变成居中卡片。
- error 靠清楚的原因和恢复操作建立信任；红色仅用于错误标记和关键句。

## 7. 动效

- 常规状态切换 `120–180ms`，使用 ease-out；大型 drawer/dialog 最长 `220ms`。
- hover 不做 `translateY`、scale 或阴影升高。允许颜色、opacity 和轻量背景变化。
- streaming、运行中和进度动效必须支持 `prefers-reduced-motion: reduce`。
- 装饰性循环动画不能成为主要状态信号，也不能持续吸引视线。

## 8. 可访问性

- 正文和控件文字与背景至少满足 WCAG AA 的 4.5:1；大字至少 3:1。当前 `--ui-text-disabled`
  在白底对比度不足，只允许用于禁用或非信息性内容。
- 所有交互都必须可键盘到达，并使用 `:focus-visible` 提供清晰焦点；不能只依赖 hover 暴露唯一操作。
- icon-only button 必须提供 `aria-label` 和 tooltip/title；状态变化需要可被辅助技术读取。
- 表单错误与对应字段建立程序化关联，不能只在页面底部显示一段红字。
- 在 `1440 × 900` 和最小 `1080 × 700` 下检查布局；另检查 125% 与 150% 缩放、英文、简体中文和
  繁体中文。截图检查不能替代真实键盘和辅助技术测试。

## 9. CSS 实现规则

### 9.1 禁止追加式覆盖

修改组件时，先找到 `styles/` 下对应 owner 文件中的权威规则并直接修改。禁止在任意文件末尾再次声明同一个选择器来“压过”
旧实现。一个基础选择器只能有一个权威定义；状态、媒体查询和父级布局差异可以单独声明。

如果旧规则分散，优先在本次触及范围内合并并删除失效声明，不保留迁移期覆盖。

### 9.2 选择器与命名

- 页面级 class 使用稳定前缀，例如 `mission-*`、`studio-*`、`evaluation-*`。
- modifier 使用 `.is-active`、`.is-disabled`、`.has-error`，不要把颜色或位置写进 class 名。
- 避免超过三层的 DOM 结构选择器和 `:nth-child()` 布局依赖。
- 禁止 `!important`，除非覆盖不受项目控制的第三方库，并在旁边说明原因。
- 不要创建只提供圆角、白底和阴影的通用 `Card`；组件名必须表达产品或交互语义。

### 9.3 Token 治理

- 新视觉值先判断是否能使用已有 token；不能时，说明新语义后再加入根 token。
- 不为单个页面创建 `--page-green-2`、`--card-radius-alt` 等局部视觉 token。
- provider logo、runtime logo 和 chart series 可以保留局部品牌/数据色，但不得影响通用控件。
- 一次改动不得引入新的字号、字重或圆角档位。

### 9.4 样式文件所有权

- Renderer 只由 `styles/index.css` 统一导入 CSS；组件和页面源码不得直接导入额外样式表。
- `foundation/` 保存 token、基础元素和应用 Shell，`components/` 保存跨页面交互组件，`features/`
  保存对应产品区域。规则放入渲染它的最浅公共 owner，不能为了方便复制到调用页面。
- 同一个“at-rule 上下文 + selector”只能由一个文件拥有。Feature 可以用更具体的父级选择器修饰共享组件，
  但不得依靠 feature 之间的导入顺序互相覆盖。
- 响应式规则、容器查询、动画和 reduced-motion 规则跟随 owner；Portal 内容归 Overlay 或共享组件，
  React Flow 覆盖保持 `.flow-canvas` 作用域。
- 不得重新创建单体 `styles.css`、`legacy.css`、`overrides.css` 或迁移层。新增或重命名文件后必须同步
  `styles/index.css`，并通过 `pnpm --filter @pragma/desktop verify:styles`。

## 10. 页面评审清单

提交 Desktop UI 改动前逐项确认：

- [ ] 页面在去掉所有装饰后，仍能靠版式和间距看懂主次。
- [ ] 一个可见任务区只有一个主按钮。
- [ ] 没有为普通 section、说明文字或空态新增卡片。
- [ ] 没有 card 套 card、双输入框边界或三重选中态。
- [ ] 选中态没有未经明确要求的侧边竖线、顶部/底部短线、角标或其他装饰性位置标记。
- [ ] 目录页进入详情后仍保留所属模块二级导航，且只替换右侧工作区内容。
- [ ] 没有直接使用原生 `select`、系统弹窗或其他会暴露平台默认外观的业务控件。
- [ ] 没有新增 raw color、任意字号、任意字重、任意圆角或 `!important`。
- [ ] hover 不改变布局；focus-visible 清楚且只有一层。
- [ ] 普通态、hover、键盘焦点、disabled、loading、empty、error 均已检查。
- [ ] Enter 提交类输入框已用中文输入法验证候选确认不会误触发提交。
- [ ] `1440 × 900`、`1080 × 700`、125%/150% 缩放和三种语言已检查。
- [ ] 页面底部留白与左右内容边距一致，内部滚动容器没有提前截断并留下额外空白。
- [ ] 新增文案、图标、badge 和分割线都承担明确的信息职责。

快速判断一个区域是否“AI 味过重”，可以问：

1. 去掉圆角、边框和阴影后，它是否仍然成立？如果成立，就去掉。
2. 这段粗体是否真的比相邻内容重要？如果不是，改为 `400/500`。
3. 这条分割线是否在区分两个用户会理解为不同的区域？如果不是，用间距。
4. 这张卡片是否可以被整体操作或比较？如果不能，它大概率只是多余容器。
5. 页面是否同时出现三个以上高对比焦点？如果是，重新确定主任务。

## 11. 渐进式落地顺序

不做全量视觉重构，按以下顺序渐进收敛：

1. **新功能立即遵守**：所有新增页面和组件只使用本规范的 token 与层级。
2. **触及即收敛**：修改旧组件时，合并它的重复选择器，停止新增任意值和追加覆盖。
3. **先基础控件**：优先统一 button、input、select、focus、badge 和 row，避免每页单独修饰。
4. **再页面骨架**：依次收敛 Settings、Usage、目录/详情页；Home 和 Flow canvas 保留其特殊结构。
5. **最后删除旧 token**：只有当引用清零且视觉 QA 完成后，才删除迁移别名和废弃规则。

任何清理不得改变业务行为、IPC 契约、页面导航或数据模型。视觉收敛与功能重构分开提交，方便评审和
回归。
