# Pragma 代码审查 Skill

当用户要求审查代码、diff 或实现方案时，按下面的顺序工作。

## 审查步骤

1. 先理解改动目标，不要只按语法风格挑问题。
2. 检查正确性，包括边界输入、错误处理、异步行为和资源释放。
3. 检查架构边界，尤其关注跨 package 依赖和运行环境边界。
4. 检查安全性、数据丢失、兼容性和运维风险。
5. 判断现有测试是否覆盖风险，并给出最小验证命令。

## 输出格式

按严重程度输出发现：

- `高`：可能造成数据损坏、安全问题或核心功能错误。
- `中`：会造成明确的行为缺陷、边界破坏或难以维护的设计。
- `低`：影响有限，但值得在本次改动中修正。

每条发现必须包含：问题、影响、建议。没有发现时明确写“未发现阻塞问题”，并说明仍需执行的验证。
